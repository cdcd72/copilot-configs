## 12. 模型大小與 Prompt 策略

Gemma 4 有多個大小與架構。提示策略應依任務複雜度與模型能力調整。

### [官方] 官方模型資訊摘要

| 模型    | 適用方向                                     |
| ------- | -------------------------------------------- |
| E2B     | 輕量、裝置端、簡單任務                       |
| E4B     | 輕量、多數日常任務                           |
| 12B     | 較穩定的一般用途、多模態與中等複雜任務       |
| 26B A4B | MoE 架構，適合較強推理、coding、agentic 工作 |
| 31B     | 高品質輸出、複雜多步驟任務                   |

### [第三方實務] Prompt 策略

| 模型大小 | Prompt 建議                                        |
| -------- | -------------------------------------------------- |
| 小模型   | 指令短、任務單一、輸出格式簡單                     |
| 中型模型 | 可使用中等長度上下文與多步驟格式                   |
| 大型模型 | 可處理更複雜 reasoning、agentic workflow、長上下文 |
| MoE      | 適合較複雜任務，但仍要明確拆分工具與輸出格式       |

### [第三方實務] 實務建議

- 小模型不要一次要求太多角色、格式、限制與長資料。
- 若小模型輸出不穩，先簡化 prompt，而不是只調參數。
- 大模型也不能依賴模糊提示；複雜任務仍要拆分。
- JSON 與工具呼叫任務建議搭配 schema、驗證與重試。
- 高價值任務建議使用較大模型並啟用 thinking。

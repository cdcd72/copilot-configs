## 1. Gemma 4 提示引導的核心觀念

**[編者建議]** 以下六點是根據官方文件與第三方實務文章整理出的工作原則，方便做為提示設計檢查框架，並非官方原文中的固定分類。

Gemma 4 的提示設計可以歸納為六個核心目標：

1. **明確角色與任務**：告訴模型它要扮演什麼角色、要完成什麼任務。
2. **提供足夠上下文**：任務背景、資料來源、限制條件、目標讀者或使用場景要明確。
3. **指定輸出格式**：若需要表格、JSON、Markdown、摘要層級、欄位結構，應直接寫在提示中。
4. **拆分複雜任務**：長流程不要一次塞入模糊指令，應拆成分析、判斷、輸出、驗證等階段。
5. **必要時啟用思考模式**：複雜推理、代理流程、多步驟問題可使用 Gemma 4 的 thinking 能力。
6. **將模型放進可驗證流程**：結構化輸出要驗證 schema；工具呼叫要由應用程式執行與防護；高風險回答要加入檢查機制。

### 推薦的通用 Prompt 骨架

```text
[角色 / 任務]
你是……請完成……

[背景 / 上下文]
以下是任務背景、資料、限制條件……

[輸入資料]
……

[要求]
1. …
2. …
3. …

[輸出格式]
請用以下格式輸出：
……

[限制]
- 不要……
- 若資訊不足，請明確指出。
- 不要捏造不存在的資料。
```

### 基本範例

```text
你是一位資深後端工程師。請審查以下 API 程式碼，重點放在：
1. 可能的錯誤
2. 安全風險
3. 效能問題
4. 可維護性
5. 錯誤處理

請用 Markdown 表格輸出，欄位包含：
- 類型
- 位置
- 問題
- 影響
- 建議修正

程式碼：
[貼上程式碼]
```

### 常見反模式

```text
幫我看一下。
```

這種提示缺少任務、評估維度、輸出格式與上下文。Gemma 4 仍可能回答，但輸出會更不穩定，也更難被重複使用。

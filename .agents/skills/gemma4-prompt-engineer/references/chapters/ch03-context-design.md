## 3. Context 設計：給 Gemma 4 足夠但不混亂的背景

**[第三方實務]** 以下 Context 設計與排版方式偏向提示工程的實務整理，用來降低長上下文混亂，並非 Gemma 官方文件中的固定範本。

Gemma 4 支援長上下文，但長上下文不代表可以把資料任意堆疊。好的 Context 設計要讓模型知道：

- 哪些資料是背景？
- 哪些資料是輸入？
- 哪些資料是限制？
- 哪些資料是應該被引用的依據？
- 哪些資料只是參考，不應該覆蓋任務規則？

### Context 排版建議

```text
任務：
請根據下列資料產出……

背景：
……

輸入資料：
[資料內容]

限制：
- 只能根據輸入資料回答。
- 若資料不足，請輸出「資料不足」並說明缺口。
- 不要加入來源沒有提到的內容。

輸出格式：
...
```

### 文件分析 Prompt

```text
我會貼上一份合約。請完成：

1. 用 5 個 bullet 摘要核心條款
2. 找出可能需要注意的不尋常條款
3. 列出所有日期、期限與金額
4. 標示任何模糊或需要確認的語句

限制：
- 只能根據合約內容回答
- 不要補充合約外的法律判斷
- 若無法判斷，請標註「需人工確認」

合約內容：
[貼上合約]
```

### 長文件的整理方式

對於長文件，建議加入「任務索引」：

```text
請先完成以下工作：
A. 找出第 1～3 節的重點
B. 找出第 4～6 節的風險
C. 最後整合成一份摘要表

請不要在 A 階段評論 B 的內容。
```

### 避免混淆的上下文標記

```text
[背景，不可直接引用]
...

[主要資料，回答必須根據此區]
...

[輸出格式，必須遵守]
...
```
